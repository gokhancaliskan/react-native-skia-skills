# Optional: 2D games

Load only for an actual game or continuous simulation task. Do not turn ordinary Skia UI into a game engine.

Keep simulation state and rendering responsibilities distinct. The simulation owns positions, velocities, lifetimes and collision state; the renderer consumes a coherent snapshot. Rendering should not advance game rules. Avoid React state updates per object per frame merely to transmit simulation state. Pick one runtime owner, and use supported serialization/transfer semantics at boundaries.

A fixed-step loop accumulates elapsed time, advances by a constant step while sufficient time remains, and renders interpolated previous/current state using `alpha = remainder / step`. Cap catch-up steps to avoid a runaway backlog after suspension; explicitly decide whether to drop time, pause or resynchronize. Interpolation adds a step of presentation latency and can be wrong across teleports/discontinuous changes. A frame callback's null first delta and background/resume gaps need tests. Fixed stepping improves repeatability; it does not by itself guarantee deterministic floating-point results across devices.

Use a clear camera mapping and its inverse for input. A parallax layer uses its own camera factor and wrapping period, not arbitrary offsets spread across drawing functions. Debug collisions by drawing the actual simulation shapes through the same camera transform, separate from decorative sprite bounds.

For sprite animation, advance frame indices by elapsed time and use valid atlas source rectangles; reset lifecycle state when reusing an entity. For particles, keep a bounded capacity and explicit expiry/overflow policy. Pool only when allocation profiling justifies it, and reset every reused field. A fixed-capacity trail is illustrated by [BoundedTrail](../examples/BoundedTrail.tsx); it is a bounded visual history, not a complete physics system. Prefer one path built from the history over one node per sample, state what happens at capacity (the oldest point is dropped), and clear the history when the effect is disabled or the scene resets so a resume does not draw a jump. Describe per-frame work accurately: copying an array and rebuilding a path each frame are allocations to profile, not zero-cost. Ribbons require handling repeated points, tangent changes, width joins and degenerate segments.

Choose a retained scene, pictures or an atlas based on the measured workload and existing architecture. A single picture per frame can still reconstruct geometry and replay expensive commands. Cull invisible work only when bounds account for blur/trail outsets and the cost is worthwhile. Measure steady gameplay, scene transitions, resume and long sessions on low-end devices. Reduced motion can disable decorative trails/parallax while keeping gameplay legible.

Sources: [frame callback](https://docs.swmansion.com/react-native-reanimated/docs/advanced/useFrameCallback/), [Atlas](https://wcandillon.github.io/react-native-skia/v2/docs/shapes/atlas/), [path hooks](https://wcandillon.github.io/react-native-skia/v2/docs/animations/hooks/). Simulation/camera guidance is general engineering reasoning, not a Skia guarantee or measured performance claim.
